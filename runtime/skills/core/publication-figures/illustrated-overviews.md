# Illustrated scientific overviews

Read this before drawing method/proposal overviews, graphical abstracts, or
poster-like figures. This is the default for those forms; it is not a mandate
to decorate quantitative plots or turn an entire report into a poster.

## Target and scope

Use the visual composition of the user's references, not merely their palette.
Default design references when none are supplied:
- [FigTree workflow](https://arxiv.org/html/2609.01006v1/method.png): nested
  pastel stage regions, layered documents, local diagrams, and a clear process.
- [Paper2Poster pipeline](https://arxiv.org/html/2505.21497v2/agent.png):
  illustrated assets, zoomed details, and interleaved visual/text explanation.
- [Paper2Poster overview](https://arxiv.org/html/2505.21497v2/overall.png):
  visually distinct creation and evaluation questions in one composition.

These are references to the displayed illustrations, not claims that FigTree's
own overview was generated by its system. Do not confuse the restrained SVG
prompt in its appendix with the appearance of its opening illustration.
Borrow design principles, not artwork, logos, claimed results, or exact layouts.

## 1. Art direction before drawing

Retrieve actual reference images or render the relevant PDF pages. Record the
URL, figure/page, local image path, and what was actually viewed. Use a vision
model if the acting model lacks image input; article text is not visual evidence.
With the reference pixels present, extract five concrete features:
composition/reading path, hierarchy, object vocabulary, palette/depth, and
text-to-visual integration. Convert each into a decision for this figure.

If vision is unavailable, check documented local gateway configuration safely
before declaring it absent; missing exported variables alone are insufficient.
Never print keys, source untrusted shell code, or send private material without
authorized scope. A listed vision model needs a successful image request before
claiming availability. Otherwise report visual verification blocked; do not
invent observations or quietly substitute a source-only aesthetic review.

## 2. Build a visual argument

- State one central question and its visible answer or proposed test. A reader
  should find the input, transformation, comparison, and output without first
  reading the caption. For proposals show planned tests, not invented successes.
- Start with two to four major semantic regions and one dominant visual anchor;
  use fewer for a simpler message or another structure when the reference calls for it.
  Differentiate their internal forms: an annotated document, a model cutaway,
  a dependency sketch, a worked example, or a comparison inset. Each object
  must identify a real entity or operation; remove objects serving only as filler.
- Integrate exact labels and calculations with the objects they explain.
  Examples belong inside the mechanism, not under unrelated decorative art.
  Show important contrasts spatially with paired regions, shared brackets, or
  matching tags; a footer mentioning them is not enough.
- For these reference styles, use pastel region fills, rounded containers, numbered tabs where order is
  meaningful, layered pages, and restrained depth cues. A small offset shadow
  or dashed zoom wedge may explain grouping or magnification. These are allowed
  in illustrated overviews; no arbitrary ban on shadows, curves, or icons.
- Distinguish arrow meanings: solid data flow, dashed annotation/zoom guide,
  feedback only when the method really contains feedback. A sealed test cannot
  feed training. Curve a connector if it improves routing; avoid crossings and
  keep arrowheads visibly attached to shafts.
- Use a clear type hierarchy, usually one heading family plus compatible body
  and math typography. Match the reference's hierarchy rather than forcing
  every element to the same serif size. Target at least 9 pt body text at final
  width; the shared 7 pt absolute floor still applies to small notation.
- Design the physical size and aspect ratio before placement. Start around
  1.6:1–2.2:1 for a wide overview when the content permits; redesign or split
  rather than shrinking labels. Do not force seven figures into one template.
- Keep labels, equations, connectors, and core diagram geometry editable in
  SVG/TikZ or an explicitly requested editable `.drawio`/presentation format. Generated raster
  assets may support illustration when useful, with provenance and exact native
  labels; they must not be fake data or an opaque replacement for the mechanism.

## 3. Style proof before bulk redesign

Produce one representative figure at intended print size, with its editable
source and rendered preview. Display it using `present_artifact`. For a full
report restyle, pause for user approval before propagating the composition,
unless the user explicitly authorizes unattended execution. Partial approval
such as “kinda like it, reinforce it” establishes direction, not final approval.
Record that distinction in the existing QA/style record. Preserve the previous
report while iterating. An approved composition is a reference, not a universal
layout template for every figure type.

## 4. Two independent acceptance gates

**A. Scientific and rendering integrity:** source-grounded entities/relations,
exact numbers and signs, no fabricated results, readable type at final size,
no clipping, occlusion, or ambiguous connectors. Apply the shared checks.

**B. Reference likeness and visual engagement:** compare the actual preview and
reference images together, not from memory. For each of the five art-direction
features, state matched/partial/missing and cite visible evidence. Ask:
- Does this read as an illustrated research overview, or a clean office flowchart?
- Which visual object explains something that text boxes alone would not?
- Are the central mechanism and experimental contrast visually prominent?
- What remains noticeably less polished or less illustrative than the target?

Before drawing, identify which extracted features are must-have for this request.
Gate B passes only when those features are visibly present and no requested
composition feature is missing; report partial nonessential matches as residual
gaps. Unresolved must-have gaps require revision or explicit user acceptance,
not a reviewer waiver. A pass on A cannot compensate for a fail on B. “No overlap,” “readable,” or
“professional” does not establish likeness. A clean but reference-dissimilar
output needs composition revision, not another color or font tweak. A model's
numeric aesthetic score is not an acceptance criterion or human approval.

Use at most three focused review/repair rounds by default. Review both the full
composition and zoomed problem regions. When vision flags a sign, glyph, or
number, check source and a high-resolution crop before changing it; reviewers
can misread plus as minus or recommend scientifically wrong repairs. Preserve
original findings and explicitly record adjudications instead of erasing them.

## Evidence to retain

In the existing figure QA JSON/notes, retain reference paths, the five design
decisions, artifact hash/version, physical size, integrity findings, likeness
findings, reviewer identity and image access, user approval status, repair rounds,
and remaining gaps. Re-review changed pages after final embedding. Never reuse
an earlier “no defects” record as approval of a newly rendered version.

## Regression cases

- “Make this overview like FigTree/Paper2Poster”: inspect reference pixels,
  create an illustrated style proof, and run both gates.
- “The charts are clean but boring”: decide whether the requested object is an
  overview or evidence plot; preserve honest chart scales, offer a separate
  illustrated overview rather than ornamental data marks.
- Seven equal rectangles with perfect typography: integrity may pass;
  reference likeness fails for these targets until composition is redesigned.
- No image input: use an authorized image-capable reviewer or mark gate B
  unverified. Never claim direct visual inspection.
- User asks for a sparse journal schematic: use the restrained schematic mode,
  not forced poster ornament; keep integrity and final-size checks.
